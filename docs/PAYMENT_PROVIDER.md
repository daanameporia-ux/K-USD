# Подключение реального платёжного провайдера

Сейчас работает `MockProvider` (`backend/app/payments/mock.py`): он выдаёт ссылки формата НСПК, подписывает callback и позволяет из админки «симулировать оплату» через тот же путь, что пройдёт настоящий платёж. Чтобы подключить реального провайдера (банк или платёжный агрегатор с СБП QR), нужно написать один класс и зарегистрировать его.

## 1. Класс провайдера

Создайте `backend/app/payments/<name>.py` с классом, реализующим протокол `PaymentProvider` из `backend/app/payments/base.py`:

| Метод | Что делает | Важно |
|---|---|---|
| `name: str` | короткое имя, например `"acme"` | совпадает с `PAYMENT_PROVIDER` и с путём callback |
| `create_qr(order_public_id, amount_rub, ttl_seconds, description) -> QrPayment` | создаёт платёж у провайдера, возвращает `provider_payment_id`, ссылку `https://qr.nspk.ru/...`, срок действия | `ttl_seconds` = сроку жизни заявки: QR должен перестать действовать вместе с заявкой. Вызывается **вне** транзакции БД, таймаут 20 с; любое исключение → заявка `failed` |
| `get_status(provider_payment_id) -> CallbackEvent \| None` | запрос статуса платежа (сверка перед истечением заявки) | `None` = ещё не оплачен. Для оплаченного верните событие со стабильным `event_key`, например `"<id>:paid"` |
| `verify_callback(headers, body) -> bool` | проверка подписи входящего callback по сырому телу | сравнивать через `hmac.compare_digest`; при `False` сервис ответит `401` |
| `parse_callback(body) -> CallbackEvent` | разбор тела callback | при неверном формате бросайте `CallbackParseError` (ответ `400`). `event_key` — уникальный id события у провайдера: по нему отсекаются повторы |

`CallbackEvent.status`: `"paid"`, `"failed"` или `"expired"`. `amount_rub` — сколько реально пришло (целые рубли); если оно не совпадёт с суммой заявки **или не передано вовсе** (`None`), заявка уйдёт на разбор без зачисления. `event_key` должен быть уникальным в пределах провайдера (в БД хранится как `<provider>:<event_key>`). `payer_info` — данные плательщика, если провайдер их отдаёт (нужны правилу антифрода B13).

HTTP к провайдеру делайте через общий `httpx.AsyncClient` с таймаутами: `build_registry` получает его параметром `http` (это `container.http`).

## 2. Регистрация

В `backend/app/payments/registry.py` в `build_registry` добавьте:

```python
if config.payment_provider == "acme":
    providers["acme"] = AcmeProvider(config.acme_api_url, config.acme_api_key, http)
```

и новые переменные окружения в `backend/app/config.py` (класс `Config`) и в `.env.example`.

## 3. Переменные окружения

- `PAYMENT_PROVIDER=acme`
- ключи провайдера (`ACME_API_URL`, `ACME_API_KEY`, `ACME_CALLBACK_SECRET` и т. п.)
- `ALLOW_MOCK_IN_PROD` больше не нужен.

## 4. Настройки у провайдера

URL для callback (webhook): `https://<ваш домен>/api/payments/callback/<name>`. Сервис отвечает `200` только после того, как зачисление сохранено; при внутренней ошибке — `500`, и провайдер должен повторить отправку. Повторы и параллельные дубли безопасны: событие с тем же `event_key` обрабатывается один раз, а одна заявка не может быть зачислена дважды.

## 5. Проверка

1. Напишите тесты по образцу `backend/tests/integration/test_orders.py` (через `respx` замокайте API провайдера).
2. На тестовом стенде провайдера проведите платёж на минимальную сумму, проверьте в админке статус заявки, запись в журнале проводок и уведомление клиенту.
3. Проверьте отказ подписи: отправьте callback с неверной подписью — должен быть `401`, заявка не меняется.
