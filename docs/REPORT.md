## Что проверено на живых данных, а что только на фикстурах

**На живых данных (11.11.2026, из облачной среды):**
- Rapira `GET /open/market/rates` — формат совпал с ТЗ; ответ сохранён фикстурой. В ручном сценарии курс 86,38 взят вживую, 1000 ₽ при наценке 5 % дали 10,99 USDT.
- TronGrid: `walletsolidity/gettransactioninfobyid` и `v1/transactions/<id>/events` по реальной USDT-транзакции и по несуществующей. В ручном сценарии верификатор вживую нашёл реальную транзакцию и корректно вернул «сумма не совпадает».
- BSC RPC `bsc-dataseed.binance.org`: `eth_blockNumber`, `eth_getBlockByNumber`, `eth_getTransactionReceipt` по реальной USDT-транзакции и `null` для несуществующей.
- `scripts/check_external.py` отработал против Rapira, TronGrid и `bsc-dataseed.binance.org` — формат совпал.

**Только на фикстурах / моках:**
- Telegram Bot API — во всех тестах и в ручном сценарии используется фейковый сервер: `api.telegram.org` из среды разработки недоступен. Живой бот не запускался.
- Запасной BSC RPC `bsc-dataseed1.defibit.io` — закрыт сетевой политикой среды; переключение на запасной RPC проверено тестами на моках.
- Неуспешная (REVERT) транзакция TRC-20, переводы другого токена, другому получателю, «мало подтверждений» в BSC — производные от реальных ответов, поправленные в тестах (`backend/tests/chain_fixtures.py`).
- Платёжный провайдер — только `MockProvider`; реальный провайдер не подключался.
- Docker-сборка в облачной среде прошла только с build-secret `extra_ca` (TLS-прокси песочницы); внутри контейнера сеть к Telegram и Rapira закрыта, сервис при этом не падает, а пишет ошибки в лог и продолжает работу.
- HTTPS через Caddy и Let's Encrypt не проверялись (нужен домен); `docker-compose.yml` для прода проверен только сборкой образов.

- [x] Порядок блокировок: заявка/вывод → пользователь; две строки `users` в одной транзакции не блокируются (B4 — отдельной транзакцией).

- [x] Уникальные индексы: депозит на заявку, хэш на сеть, одна активная заявка, `event_key` callback, `idempotency_key` для заявок и выводов.

## Независимое ревью

После этапа 13 проект построчно проверили 7 независимых ревьюеров (деньги и покупки; выводы и блокчейн; антифрод, статистика и курс; Telegram-слой; авторизация и API; фронтенд; инфраструктура и полнота ТЗ). Подтверждённые находки исправлены, на каждую добавлен регрессионный тест; перечень — в `docs/DECISIONS.md`, пп. 51–68. Самые важные: один перевод в блокчейне больше не может закрыть два вывода; QR-код на экране оплаты в Mini App не отображался; неэкранированный текст мог «потерять» уведомление клиенту об отклонении; лимит неудачных входов обходился параллельными запросами; бэкап мог молча сохраняться пустым.

## Что сделать владельцу

1. Развернуть по `README.md` на сервере с доменом.
2. Запустить `docker compose exec app python scripts/check_external.py` на сервере.
3. Пройти сценарий из README (шаг 7) с живым ботом.
4. Подключить реального платёжного провайдера по `docs/PAYMENT_PROVIDER.md`; до этого держать `PAYMENT_PROVIDER=mock`.
