# K-USD — бот покупки USDT по QR СБП

Telegram-бот и мини-приложение: клиент покупает USDT за рубли по QR-коду СБП, USDT зачисляются на внутренний баланс по курсу Rapira с вашей наценкой, затем клиент выводит их на кошелёк (TRC-20 или BEP-20). Выводы исполняет оператор, система сама проверяет транзакцию в блокчейне. Есть админка — в браузере и внутри Telegram.

Эта инструкция — для запуска без технической подготовки. Делайте шаги по порядку.

---

## Что понадобится

- Telegram-аккаунт.
- Сервер (VPS) с Ubuntu 22.04 или новее, 2 ГБ памяти, 20 ГБ диска. Подойдёт любой хостинг (Timeweb, Selectel, Hetzner, DigitalOcean и т. п.).
- Домен (например, `usdt-shop.ru`). Telegram открывает мини-приложения только по `https://`, поэтому без домена не обойтись. Сертификат HTTPS выпустится автоматически и бесплатно.

## Шаг 1. Создайте бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`.
2. Придумайте имя и username бота (должен заканчиваться на `bot`).
3. BotFather пришлёт **токен** вида `1234567890:AAH...`. Сохраните его — это пароль от бота, никому не показывайте.

## Шаг 2. Узнайте свой Telegram ID

Напишите боту [@userinfobot](https://t.me/userinfobot) — он ответит числом `Id: 123456789`. Это ваш Telegram ID, он понадобится, чтобы сделать вас главным администратором.

## Шаг 3. Арендуйте сервер и установите Docker

1. Купите VPS с Ubuntu 22.04+. Хостинг пришлёт IP-адрес и пароль `root`.
2. Подключитесь к серверу. На Windows — программой PowerShell, на macOS — «Терминалом»:

```bash
ssh root@IP_ВАШЕГО_СЕРВЕРА
```

3. Установите Docker одной командой:

```bash
curl -fsSL https://get.docker.com | sh
```

## Шаг 4. Купите домен и направьте его на сервер

1. Купите домен у любого регистратора.
2. В панели управления доменом (раздел DNS) создайте **A-запись**: имя `@` (или поддомен, например `usdt`), значение — IP вашего сервера.
3. Подождите 5–30 минут, пока запись заработает. Проверить можно командой `ping ваш-домен` — должен отвечать IP сервера.

## Шаг 6. Запустите

```bash
docker compose up -d --build
```

Первая сборка занимает 3–10 минут. Проверить, что всё работает:

```bash
docker compose ps
```

Все сервисы должны быть в состоянии `running` (у `app` — `healthy`). Откройте в браузере `https://ваш-домен/healthz` — должно показать `{"status":"ok"}`.

При запуске сервис сам настраивает бота: адрес webhook, список команд и кнопку «Приложение» в меню чата.

## Шаг 7. Проверьте бота и админку

1. Напишите своему боту `/start` и пройдите регистрацию — появится главное меню.
2. Напишите `/admin` — бот пришлёт кнопку открытия админки. Админка откроется внутри Telegram без пароля.
3. Пробная покупка: «💵 Купить USDT» → сумма → «Подтвердить». В админке откройте «Заявки» → заявку → «Симулировать оплату». Бот пришлёт «Оплата получена», USDT появятся на балансе.

## Сотрудники

Роли: **админ** (всё) и **оператор** (очередь выводов, просмотр заявок и клиентов).

Добавить сотрудника: админка → «Сотрудники» → «Добавить»:
- **по Telegram ID** — доступ появляется сразу (ID сотрудник узнаёт у @userinfobot);
- **по @username** — создаётся приглашение на 48 часов. Сотрудник должен написать боту `/start`, после этого доступ появится, а вам придёт уведомление.

Сотрудник открывает админку командой `/admin` в боте.

Главные администраторы из `SUPERADMIN_TG_IDS` создаются автоматически; через интерфейс их нельзя удалить или понизить. Чтобы лишить человека этого статуса, уберите его ID из `SUPERADMIN_TG_IDS` и перезапустите (`docker compose up -d`): он станет обычным админом, и его можно будет понизить или удалить в «Сотрудниках».

Запасной способ добавить сотрудника — из командной строки сервера:

```bash
docker compose exec app python -m app.cli create-staff --tg-id 123456789 --role operator
```

### Вход в админку из браузера

1. Откройте админку в Telegram (`/admin`) → «Профиль» → «Веб-доступ»: придумайте логин и пароль (не короче 12 символов).
2. Там же включите TOTP: отсканируйте QR-код приложением Google Authenticator, Яндекс Ключ или аналогом и введите код.
3. Теперь вход в браузере: `https://ваш-домен/admin/` → логин, пароль и 6-значный код из приложения.

Без включённого TOTP вход из браузера невозможен. После 5 неудачных попыток вход блокируется на 15 минут.

### Служебный чат для уведомлений (необязательно)

1. Создайте группу в Telegram, добавьте туда бота и сотрудников.
2. Узнайте ID группы: добавьте в неё [@getidsbot](https://t.me/getidsbot) — он пришлёт число вида `-1001234567890`.
3. Впишите его в `.env` как `STAFF_CHAT_ID` и перезапустите: `docker compose up -d`.

В чат приходят: новые выводы, срабатывания антифрода, проблемы с курсом и провайдером, ручные корректировки и принудительные закрытия выводов.

### Резервные копии

Контейнер `backup` раз в сутки сохраняет копию базы и хранит 14 дней. Посмотреть копии:

```bash
docker compose exec backup ls -lh /backups
```

Если копирование не удалось или последняя копия старше 26 часов, бот пришлёт предупреждение в служебный чат.

> **Важно.** Копии лежат на том же сервере, что и база. Если сервер или диск будут потеряны, пропадут и база, и все копии. Команда `docker compose down -v` тоже удаляет и базу, и копии — не используйте ключ `-v`. Регулярно забирайте копии на другой компьютер или сервер. В копии есть балансы клиентов и служебные данные сотрудников — храните её в надёжном месте.

Скопировать копию с сервера к себе (выполняйте на своём компьютере):

```bash
scp root@IP_СЕРВЕРА:/var/lib/docker/volumes/kusd_backups/_data/ИМЯ_ФАЙЛА.sql.gz .
```

### Восстановление из резервной копии

1. Остановите приложение:

```bash
docker compose stop app caddy
```

2. Пересоздайте базу и загрузите копию (подставьте имя файла):

```bash
docker compose exec postgres sh -c 'dropdb -U kusd kusd && createdb -U kusd kusd'
```

```bash
docker compose exec backup sh -c 'gunzip -c /backups/kusd-ДАТА.sql.gz | psql -q -v ON_ERROR_STOP=1 --single-transaction'
```

3. Запустите снова:

```bash
docker compose up -d
```

### Бот не отвечает

1. Проверьте логи: `docker compose logs --tail=100 app` (ищите `bot_setup_failed` или `tg_network_error`).
2. Если менялись домен или `TELEGRAM_WEBHOOK_SECRET`, или сервер стартовал раньше, чем заработал DNS, — заново зарегистрируйте webhook (приложение и само повторяет попытки каждые несколько минут):

```bash
docker compose exec app python -m app.cli set-webhook
```

3. Проверьте `https://ваш-домен/readyz`: в ответе `bot_configured` должно быть `true`.

## Как работает сервис (кратко)

- **Курс** берётся с Rapira каждые 45 секунд. Если курс устарел больше чем на 3 минуты или резко скакнул (больше 3 %), покупки останавливаются, админам приходит уведомление. Скачок можно подтвердить или задать ручной курс в «Настройках». Если ручной курс сильно отличается от биржевого, админка попросит подтвердить его ещё раз — это защита от опечатки.
- **Расчёт:** `USDT = сумма × (1 − наценка) / курс`, всегда с округлением вниз. Пример: 1000 ₽, наценка 5 %, курс 100 → 9,50 USDT.
- **Заявка** живёт 15 минут. Если оплата пришла с другой суммой или после закрытия заявки — заявка уходит на разбор в админку без зачисления.
- **Вывод:** клиент указывает сеть, адрес и сумму; деньги блокируются. Оператор отправляет USDT со своего кошелька и вносит хэш транзакции — система сама проверяет получателя, сумму и токен в блокчейне и только тогда закрывает вывод.
- **Антифрод:** 3 неоплаченных заявки подряд — клиент помечается подозрительным, 5 подряд или конверсия ниже 80 % — создание заявок блокируется до ручной разблокировки админом. Дополнительные правила (B1–B14) включаются в «Настройки → Антифрод».
- **Глобальные рубильники** «Покупки» и «Выводы» — в «Настройках».

## Для разработчика

Локальный запуск без домена (бот в режиме polling, mock-провайдер, без Caddy; нужен `BOT_TOKEN` тестового бота в `.env`):

```bash
docker compose -f docker-compose.dev.yml up --build
```

Бот работает сразу. Mini App и админка внутри Telegram открываются только по `https://`, поэтому для их проверки пробросьте порт 8000 HTTPS-туннелем (например, `cloudflared tunnel --url http://localhost:8000`) и укажите выданный адрес в `PUBLIC_BASE_URL`. База dev-окружения доступна на `127.0.0.1:5433` (переменная `DEV_PG_PORT`).

Бэкенд и тесты (нужен PostgreSQL 16, `TEST_DATABASE_URL`):

```bash
cd backend && python3.12 -m venv .venv && .venv/bin/pip install -c requirements.lock -e ".[dev]"
```

```bash
./check.sh
```

Фронтенд (smoke-тест использует Playwright с Chromium: `npm install --no-save playwright@1.63.0 && npx playwright install chromium`):

```bash
cd frontend && npm ci && npm run typecheck && npm test && npm run build && npm run e2e
```

Структура: `backend/app` — FastAPI, собственный Telegram-клиент (без библиотек для ботов), сервисы, фоновые задачи; `frontend/client` — клиентский Mini App; `frontend/admin` — админка (браузер и Mini App); `frontend/shared` — общий код.
